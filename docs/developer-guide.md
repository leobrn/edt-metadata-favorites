# EDT Metadata Favorites — руководство разработчика

Краткая карта устройства плагина и контрактов, которые важно сохранить при изменениях.
Пользовательские сценарии описаны в [руководстве пользователя](user-guide.md).

## Стек и структура

- Eclipse/OSGi и Common Navigator Framework;
- API метаданных 1С:EDT и EMF;
- SWT/JFace;
- Maven Tycho и JUnit 4.

Плагин работает на Java 17. Для сборки нужны JDK 21+, Maven 3.9.9+ и target platform
из `app/targets/default/default.target`.

```text
app/
  bom/                                      общая конфигурация Maven/Tycho
  bundles/edt.metadata.favorites/           код OSGi bundle
  features/edt.metadata.favorites.feature/  устанавливаемая feature
  repositories/edt.metadata.favorites.repository/
                                             p2 update site
  targets/default/                          target platform 1С:EDT
tests/edt.metadata.favorites.tests/          автоматические тесты
```

В bundle файлы `plugin.xml`, `plugin.properties` и `META-INF/MANIFEST.MF` задают интеграцию
с Eclipse, подписи, зависимости и среду выполнения. Namespace плагина — `edt.metadata.favorites`.

## Архитектура

```text
plugin.xml ─> меню и обработчики
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
  PinOperations         FavoritesManagementDialog
        │                 (отложенные изменения)
        └───────────┬───────────┘
                    ▼
                 PinStore
          ┌─────────┼─────────┐
          ▼         ▼         ▼
     декоратор   фильтр    состояние диалога
```

Ключевые инварианты:

- `Activator` владеет одним лениво созданным `PinStore` для текущего workspace.
- Доступ к проектам, UUID, FQN и EMF-модели EDT сосредоточен в `MetadataPinSupport`.
- Доступ к `CommonNavigator`, его viewer и активным фильтрам сосредоточен в `NavigatorAccess`.
- Команды Навигатора, редактора и горячая клавиша изменяют состояние через `PinOperations`.
- Диалог накапливает изменения по проектам и записывает их только после нажатия **ОК**.
- Избранный проект и избранные объекты внутри него — независимые состояния.
- После немедленного изменения `PinOperations.refreshUi()` согласованно обновляет декоратор,
  кнопку редактора и активный фильтр Навигатора.

## Основные компоненты

Исходники находятся в
`app/bundles/edt.metadata.favorites/src/edt/metadata/favorites/`.

| Компонент | Ответственность |
|---|---|
| `Activator`, `PinStore` | Жизненный цикл, загрузка и сохранение состояния |
| `PinnedObjectKey`, `PinTarget` | Хранимый ключ и переносимое представление объекта |
| `MetadataPinSupport` | Граница интеграции с API и EMF-моделью EDT |
| `NavigatorAccess` | Поиск Навигатора/viewer и проверка активного фильтра |
| `PinOperations` | Немедленные операции и обновление UI |
| `PinMenuContribution`, `*Handler` | Контекстное меню и команды Eclipse |
| `FavoriteTreeModel`, `FavoriteTreeNode` | Независимая проекция конфигурации для диалога |
| `FavoritesManagementDialog`, `FavoriteTreeSearch` | Пакетное управление и поиск |
| `FavoritesQuery`, `PinnedOnlyFilter`, `ToggleFilterHandler` | Чтение избранного и фильтрация CNF |
| `PinDecorator` | Значок избранного |
| `FavoriteUiLimits` | Общие ограничения автоматического раскрытия |

## Хранение и разрешение состояния

Файл находится в
`<workspace>/.metadata/.plugins/edt.metadata.favorites/pinned.yaml`.
Ключ объекта состоит из имени Eclipse-проекта и UUID; FQN хранится только как читаемая метка.

`PinStore` синхронизирует операции, лениво загружает данные и сохраняет их через временный файл
с атомарной заменой, если она поддерживается. При ошибке чтения или неизвестной новой версии формата
изменения блокируются, чтобы не затереть исходный файл.

Формат файла версионируется отдельно от bundle. При его изменении нужно обновить
`CURRENT_FORMAT_VERSION`, чтение, запись и тесты совместимости в `PinStoreTest`.

Для объектов хранятся три набора:

- индивидуальные отметки;
- корни рекурсивно выбранных веток;
- исключения внутри таких веток.

UUID-путь проверяется от объекта к предкам. Сначала учитывается индивидуальная отметка самого объекта,
затем ближайшее исключение или рекурсивный корень. Индивидуальная отметка предка не наследуется.

`FavoritesQuery.getRevision()` выражает изменение результатов запросов и инвалидирует кэши
фильтра. `ProjectPinSnapshot` позволяет диалогу прочитать состояние проекта без обращения
к хранилищу для каждого узла. Оба входа разрешения эффективного закрепления делегируют одному
чистому алгоритму.

Важно: `FavoriteTreeModel` — оптимизированная UI-проекция, а не полный реестр объектов.
Нельзя передавать собранные из неё UUID в `PinStore.pruneMissingObjects()`; очистка допустима
только по авторитетному полному набору UUID проекта.

## Диалог, поиск и фильтр

`FavoriteTreeModel` строит дерево непосредственно из `Configuration`, группирует `MdObject`
и пропускает containment-пути, которые не могут привести к объектам метаданных. Дерево каждого
проекта кэшируется до закрытия диалога.

Поиск работает над подготовленными полями `FavoriteTreeNode`, не обращаясь в фоне к SWT или EMF.
Он запускается в Eclipse `Job`; поколение запроса и имя проекта не позволяют применить устаревший
результат. UI обновляется через `Display.asyncExec`.

`PinnedOnlyFilter` оставляет избранные элементы и пути к ним. У него два кэша:

- наличие избранного в проекте — до изменения `FavoritesQuery.getRevision()`;
- наличие подходящего потомка — только на один проход UI, потому что дерево EDT меняется независимо
  от хранилища.

Eclipse создаёт фильтр через публичный конструктор без аргументов; он получает текущий `PinStore`
из `Activator`. Package-private конструктор принимает `FavoritesQuery` и позволяет без SWT/EDT
проверить project fast-path и инвалидацию долгоживущего кэша. Ветки объектов метаданных и
рекурсивный обход остаются интеграционно и вручную проверяемыми.

`ToggleFilterHandler` всегда передаёт CNF полный набор активных фильтров, иначе штатные фильтры
пользователя будут отключены. `FavoriteUiLimits.MAX_AUTO_EXPANDED_OBJECTS` ограничивает только
автоматическое раскрытие, но не результаты.

Идентификатор Навигатора `com._1c.g5.v8.dt.ui2.navigator` объявлен для Java-кода в
`NavigatorAccess` и отдельно используется декларативно в `plugin.xml`. При смене версии EDT
оба места проверяются вместе.

## Как вносить изменения

- Новая немедленная команда: объявление в `plugin.xml`, подпись в `plugin.properties`,
  обработчик, операция в `PinOperations` и тест.
- Новый тип или способ обхода метаданных: изменение в `MetadataPinSupport` или
  `FavoriteTreeModel` и тест структуры дерева.
- Изменение хранения: миграция формата и тесты `PinStoreTest`.
- Изменение фильтра или команд: автоматический структурный тест и ручная проверка в 1С:EDT.

Не переносите работу с `PinStore` в UI-классы без необходимости и не дублируйте обход EMF
за пределами `MetadataPinSupport` и `FavoriteTreeModel`.

## Сборка и проверка

```shell
mvn -f app/pom.xml clean verify
```

Тесты покрывают хранилище и рекурсивное состояние, защиту неизвестной и повреждённой версии
формата, revision состояния, массовые исключения, эквивалентность двух входов разрешения
эффективного закрепления, project fast-path фильтра и его revision-кэш, построение и поиск по
дереву, а также критические объявления `plugin.xml`. Поведение объектов в фильтре, Навигатора,
редактора и горячих клавиш дополнительно проверяется в реальном EDT по
[чек-листу ручного тестирования](manual-testing-checklist.md).

Release-комплект собирается командой:

```powershell
.\build-release.ps1
```

Правила подготовки изменений приведены в [CONTRIBUTING.md](CONTRIBUTING.md).
