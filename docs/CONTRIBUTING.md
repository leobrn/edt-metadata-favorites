# Участие в разработке

Перед отправкой изменений:

1. Создайте отдельную ветку от актуальной основной ветки.
2. Ограничьте изменение одной задачей и добавьте тесты для новой логики.
3. Обновите руководство пользователя при изменении поведения, руководство разработчика —
   при изменении архитектуры, а историю изменений — для значимого изменения.
4. Выполните `mvn -f app/pom.xml clean verify`.
5. Пройдите все применимые пункты
   [чек-листа ручного тестирования](manual-testing-checklist.md).
6. Опишите назначение изменения, результаты автоматической и ручной проверки,
   пропущенные пункты чек-листа с обоснованием и известные ограничения.

Полный чек-лист обязателен перед выпуском релиза. Для изменений только в документации допускается
не выполнять проверки в EDT, если это явно указано в описании изменения.

Сообщение об ошибке должно содержать версию 1С:EDT, шаги воспроизведения,
ожидаемый и фактический результат, а также релевантный фрагмент журнала ошибок.
